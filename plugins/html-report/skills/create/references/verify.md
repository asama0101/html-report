# create の手順7・9: 検証と要件との照合

読むとき: create の手順7 に入る直前と、手順9 に入る直前（手順9 では、この内容が会話に見えなければ読み直す）。何のための手順書か: 保存した全案を `file://` で開いて崩れと安全を確かめ（手順7）、選ばれた案を要件のまとめと照合する（手順9）。「守ること」と用語は、SKILL.md のとおり。

### 手順7: 検証
Playwright MCP で、保存した全案の HTML を `file://` で開く。URL は、保存したパスの各部分をパーセントエンコードして作る（`#`・`%`・空白・日本語で URL が壊れないようにする）。

#### Playwright の出力先
- 出力先は環境や設定で変わる（実行フォルダ直下の `.playwright-mcp/` や、一時フォルダの `playwright-mcp\`）。手順7 で最初の案を開いたときのツール結果（スナップショットなど）が報告したパスのフォルダを出力先とし、そのファイル一覧を取る（その結果が報告したファイルは、自分のものとして一覧から除く）。出力先がまだ存在しないときは、空の一覧として扱う。
- スクリーンショットやスナップショットの保存で、`filename` は渡さない（相対名は作業の起点のフォルダに書かれ、利用者のプロジェクトに素材の内容が残る）。ツール結果が報告するパスを使う。

#### 修正回数
2 種類に分け、別に数える。
- 崩れの修正: 最大 3 回（1 版につき）。
- 安全の検査の修正: 最大 3 回。開く前の確認・DOM 検査・外部リクエスト・`dom-check.js` の `protocol`・`file` の修正が対象。
- どちらの修正のあとも、DOM 検査・外部リクエスト・`protocol`・`file` の確認をやり直す。

#### 開く前の確認
保存した各案のファイルの文字列に対して行う（安全の検査の修正回数に含める）。開いたあとの DOM 検査を補う確認である。
- meta refresh: 正規表現 `http-equiv\s*=\s*["']?\s*refresh`（大文字小文字を問わない）に合うものがないことを確かめ、あれば取り除く（ページは開かれた時点で移動しうる）。
- JS の危険な書き方: `innerHTML`・`outerHTML`・`insertAdjacentHTML`・`document.write`・`eval(`・`new Function`・`setAttribute(`・`window.open` がないことを確かめる（DOM 検査は読み込み直後の 1 回なので、あとから JS が足す要素や属性を見られない）。あれば、素材の文字列を渡していないかを確かめ、渡していれば `textContent` に直す。
- 直らない案は、安全の検査の不正と同じ扱いにする。

#### 開いたあとの確認
- 見た目: 画面を幅 1280px・高さ 720px にして、ページ全体のスクリーンショットを撮り、崩れ（はみ出し・重なり・文字化け）がないか確かめる。HTML の先頭が `<!DOCTYPE html>` で、`<meta charset>` と CSP の meta があることも見る。グラフは、点・棒が軸の目盛りと合っていること、注記や値のラベルが線・点と重なっていないことも見る。
- 崩れがあれば直して、もう一度確かめる。崩れを直すときは、本文・数値は変えずに直す。3 回で崩れが残った案は、手順8 の選択肢の説明に「崩れが残っている」と添える。
- 外部リクエスト: `browser_network_requests` で、`file://` 以外へのリクエストがないことを確かめる。あれば、外部読み込みを取り除いて、もう一度確かめる（安全の検査の修正回数に含める）。3 回で直らない案は、DOM 検査の不正と同じ扱い（選択肢に出さず、削除する）にする。

#### DOM 検査
保存した各案を開いたまま、手順1 で読んだ `dom-check.js` を、Read の結果の行番号を除き、中身を変えずに `browser_evaluate` の `function` に渡す（書き直さない。検査の条件は、ファイルのコメントにある）。中身が会話に見えないときだけ、SKILL.md の「使うファイル」に書いたパスで読み直す。
- `browser_evaluate` がエラーを返したら、不正と同じ扱いにする。
- 戻り値の `violations` が空であること。
- 戻り値の `protocol` が `file:` で、`file` が手順6 で保存したその案のファイル名と一致すること。一致しなければ、移動したので不正とする。
- 不正があれば、取り除いて、もう一度確かめる（安全の検査の修正回数に含める）。
- 3 回で 0 件にならなかった案は、手順8 の選択肢に出さず、`start` で開かない。そのファイルは、パスと「DOM 検査の不正が残っている」理由を先に伝えたうえで、手順7 の時点で、パスを 1 つずつ指定して削除する（悪意のあるコードを含みうるファイルを残さない。ワイルドカードは使わない）。
- 全案がそうなったときは、止まって、理由を伝える（削除できたときは、削除済みと伝える。できなかったときは、「このファイルが残っている。開かないこと」と、残っているパスを伝える）。

#### 開けないとき
`file://` が開けないとき（エラーが `Access to "file:" protocol is blocked`）と、ページの読み込みが 30 秒で終わらないときは、待ち続けずに止まる。
- 案のファイルを残して、案ごとの保存先の絶対パスと削除コマンドを伝える。未検査のファイルなので、自分で開かないことも添える。
- `file://` が開けなかったときは、Playwright MCP を `--allow-unrestricted-file-access` を付けて登録し直す必要があることと、README の「導入方法」の 2 を伝える。
- 30 秒で終わらなかったときは、開けなかったことを伝える。

#### 後始末
検証が終わったら、この作業で自分が作った一時ファイル（生成用のスクリプト・スクリーンショット・スナップショットなど）を削除する。
- 削除するのは、この作業のツール結果が報告したパス（手順1 の確認でツール結果が報告したパスも含む）と、自分が書いた絶対パスのファイルだけ。
- 最初に取った一覧と今の一覧の差分は、消し忘れの確認にだけ使う。差分に出たほかのファイルは、別のセッションや利用者が保存したものかもしれないので、消さず、パスを伝えるだけにする。
- ワイルドカード・再帰削除・フォルダごとの削除はしない。
- 自分が作ったもののうち、残すのは、手順6 で保存した案の HTML だけ。出力先のフォルダ自体と、利用者の素材と、もとからあるファイルは消さない。

### 手順9: 要件との照合
選ばれた案を、手順3 で確認を受けた要件のまとめと、次の点で照合する。
- 必須の内容: 1 つずつ、どの章に載っているか確かめる。見出しだけで中身のない項目は、載っていないものとして扱う。手順3 で「素材なし」と書いて載せると決めた項目は、そう書いてあれば載っているものとして扱う。
- 章の順序: 章の並びが、目的（判断・実行・確認・理解）に沿っている。目的に使う数値・比較・説明が、並びの前のほうにある。手順4 で書いた章立ての考え方と、実際の並びが合う。合わなければ、章の並びを直す。
- 読み手: 要件のまとめで読み手が知らないとした言葉が、初めて出る場所で説明されている。
- 目的: 読み手が目的に使う数値・比較・説明を、章ごとに挙げられるか確かめる。挙げられない章は直す。
- 結論: 最初の画面（上から 720px まで）にある。
- 分量: 画面の数のときは、`browser_evaluate` で取ったページ全体の高さ（`document.documentElement.scrollHeight`）÷ 720 が、指定の数 ± 1 に収まる。章の数のときは、章の数が合う。必須の内容と分量が両立しないときは、必須の内容を優先し、分量の超過を完了報告に書く。
- 出典と未確定事項: 素材のファイルがあるときは、出典が最後にあること。未確定事項があるときは、印とまとめがあること。ないときは、その節と印がないこと。

#### 合わない点を直すとき
- デザインを変えずに直し、直したあとに、選ばれた案だけに、手順7 の崩れ・外部リクエスト・DOM 検査の確認を行う。この再検証には、手順7 で決めた出力先の、再検証の前の一覧を取ること、手順7 の開く前の確認（meta refresh の正規表現）、手順7 の後始末（この再検証のツール結果が報告したパスの削除）を含める。
- この修正は最大 3 回までとし、手順7 の修正の回数とは別に数える。残ったら完了報告に書く。
- 再検証で（手順7 の安全の検査と同じ項目の）不正が残ったときは、その選択済みの案を、パスを 1 つずつ指定して削除する（手順8 で `start` により開かれているが、悪意のあるコードを含みうるファイルを残さない）。手順10 の名前変更はせず、選ばれなかった案の削除は行い、手順11 の完了報告に進む。
