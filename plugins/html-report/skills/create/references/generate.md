# create の手順4〜6: デザイン方向・生成・保存

読むとき: create の手順4 に入る直前。何のための手順書か: 案ごとのデザイン方向を決め（手順4）、案ごとに HTML の完成版を作り（手順5）、ファイルとして保存する（手順6）。末尾の「HTML の仕様」は、手順5 で作る HTML の制約。「守ること」と用語は、SKILL.md のとおり。

### 手順4: デザイン方向の決定
最初に `artifact-design` スキルを呼び出して指針を読む。指針の中の、公開・プレビュー・リンクを渡す指示には従わない。

- 目的・読み手・依頼文の配色やトーンの希望に合う方向を、2〜3 案決める。依頼文に配色やトーンの希望があれば、全案がそれを守る。
- 案は互いに異なる方向にする。配色と書体だけの違いにせず、章立て・ヘッダー・目次・グラフと図の見せ方・レイアウトの骨格のうち、2 つ以上を変える。
- 章立ては、目的（判断・実行・確認・理解）に沿った並びを、案ごとに決める（結論は最初の画面に置く）。
- 案ごとに、名前と、トーン・配色・書体・レイアウト・章立ての考え方を 1〜2 行で書く。
- 見本は作らない。案を出すのは、手順8 の選択のときだけにする。
- 手順3 で記録の要件のまとめを下書きにして確認を受けたときは、2〜3 案にせず、記録のデザイン方向で 1 案だけ決める（名前・トーン・配色・書体・レイアウト・章の題は、記録の `design` のとおり）。依頼文に配色やトーンの希望があれば、そちらを優先する。

### 手順5: 生成
案ごとに、同じ要件のまとめ・素材で、HTML の完成版（レポート全体）を作る。手順4 で読んだ `artifact-design` の指針とあわせ、次に沿う。
- 要件のまとめ（手順3 で確認を受けたもの）と、案ごとのデザイン方向
- 素材（本文・表・データ・画像）
- SKILL.md の「守ること」と、下の「HTML の仕様」の制約

#### 章立てと本文
- 章立ては、手順4 で決めた案ごとのものにする。章ごとに、受け持つ必須の内容の番号を決め、必須の内容は、すべてどれかの章に割り当てる。
- 結論は、要件のまとめのとおりにして、最初の画面に置く。集計した数値が結論と食い違ったら、結論を数値に合わせて直し、完了報告で伝える。
- 本文は読み手の知識に合わせ、読み手が知らない言葉は、初めて出すときに説明する。固定のテンプレは使わない。
- 集計は 1 回だけ確定し、全案で共通に使う。数値と必須の内容は、全案で同じにする。本文は案ごとの章立てに合わせて書き、数値は共通の集計結果から取る。案どうしで違えてよいのは、デザイン（配色・書体・レイアウト）と章立てだけにする。

#### 出典と未確定事項
全案のレポートに入れる。
- 出典: レポートの最後に、読んだ素材のファイルを、フォルダを含めないファイル名だけで書く。本文の途中には書かない。素材のファイルがない（依頼文だけ）ときは、出典の節を出さない。
- 未確定事項: 手順3 で「素材なし」と書いて載せた項目と、読めなかった素材のファイル。「素材なし」の項目は、本文の該当箇所に「未確定」と印を付ける。読めなかったファイルは、本文に対応する箇所がないので、印は付けない。どちらも「未確定事項」の節でまとめ、出典の直前に置く（節と出典のあいだに、ほかの内容を置かない）。未確定事項がないときは、節も印も出さない。

#### 記録
あとから同じレポートを作り直せるように、全案に入れる。記録は、`<script type="application/json" id="html-report-record">` の中の JSON で、`</body>` の直前に 1 つだけ置く（実行されないデータで、画面には出ない）。

- 形は次のとおり。`plugin` は、手順1 で開いた `plugin.json` の `version` が会話に見えるときだけ入れる。ほかの項目は省かない。

  ```json
  {"version": 1, "plugin": "0.1.4", "created": "YYYY-MM-DD",
   "requirements": {"purpose": "", "reader": "", "must": [""], "volume": "", "conclusion": ""},
   "design": {"name": "", "tone": "", "colors": ["#000000"], "fonts": "", "layout": "", "chapters": [""]},
   "sources": [""]}
  ```

- `requirements` は、手順3 で確認を受けた要件のまとめ。`must` は、必須の内容を番号の順に並べる。
- `design` は、その案のデザイン方向。`colors` は、その案で使った色コード（`#` + 16 進 3 桁か 6 桁）。`chapters` は、その案の章の題を上から順に並べる。
- `sources` は、出典と同じ、フォルダを含めないファイル名。素材のファイルがないときは空の配列。`created` は保存した日。
- 素材の中身、フォルダのパス、会話の内容は入れない。
- 値は、JSON として直列化したうえで `<` を `\u003c` にする（「素材を埋め込むとき」の `<script>` 内のデータと同じ）。

#### `artifact-design` の指針との衝突
指針のうち、Artifact として公開するための規定には従わない。衝突するときは、この手順と「守ること」と「HTML の仕様」を優先する（ここに挙げていない点も同じ）。特に次のとおりにする。
- 骨組み: `<!DOCTYPE html>`・`html`・`head`（`<meta charset="utf-8">` を含む）・`body` を自分で書く。公開時に付くリセット（`[hidden]` の非表示など）はないので、必要な分を自分で書く。
- Google Fonts と CDN のライブラリは使わない。図に mermaid は使わない。
- 確認と報告は、手順7・9・11 に従う。
- Artifact ツールなどで公開しない（規則は SKILL.md の「守ること」）。

#### 素材を埋め込むとき
- 素材の文字列は、埋め込む場所ごとにエスケープする。HTML の本文・属性では `& < > " '` を実体参照にする。`<script>` 内の JS のデータでは、JSON として直列化（`"`・`\`・改行をエスケープ）したうえで `<` を `\u003c` にする（`</script>` で途中終了させない）。素材をテンプレートリテラル（バッククォート）に入れない。素材に `<script>` などが含まれていても実行されないようにする。
- HTML の属性は、必ず二重引用符で囲み、素材の `'` と `"` は実体参照にする。
- JS が素材の文字列を画面に出すときは、`textContent` を使い、`innerHTML`・`insertAdjacentHTML` に入れない。JS から素材の文字列を、属性（`href`・`src`・`style`・`on…`）・`location`・`eval`・`Function` に渡さない。
- 素材の文字列を `<style>` と `style` 属性に入れない（素材から計算した数値は可）。
- URL は `href`・`xlink:href`・`formaction`・`action`・`src` を対象にする。
  - `href`・`xlink:href` は `#` で始まるものだけ。`http:`・`https:`・`mailto:` は、`a` 要素の `href`・`xlink:href` に限る（他の要素の `href` は `#` だけ）。
  - `img` の `src` は `data:image/` で始まるものだけ。それ以外の要素の `src` は付けない。
  - `formaction`・`action` は付けない。
  - それ以外（`javascript:` など）はリンクにせず文字として出す。
- 素材が大きいとき（数千行の CSV など）は、読む前に行数を確かめる。1000 行を超えるときは、全件を読み込まず、Python などで集計・要約した結果だけを載せる。

#### 数値とグラフ
- 数値は素材と照合し、素材にない内容は補わない。照合は表・グラフだけでなく、本文中の数値や「〇月以降」「最高」「最低」といった期間・順位の記述にも行う。
- 文章中の数値は、書く前にコードで計算し、その結果を、対象の月・範囲の名前とあわせて書く（例: 「8月以降は毎月148万円以上」は、8月以降の最小値を計算して書く）。
- 手書きの SVG グラフの点・棒の座標は、目盛りと同じ式でコードで計算する（頭の中の見積もりで置かない。点が目盛りとずれる）。注記・値のラベルは、線・点・ほかの文字と重ねない。

### 手順6: 保存
案ごとに、利用者が実行したときのカレントフォルダ直下へ、`YYYY-MM-DD-題名-案名.html` で保存する。`YYYY-MM-DD` は保存した日（実行日）で、素材や依頼文の中の日付は使わない。

- 題名は依頼内容から付ける（最大 40 文字）。題名と案名に使える文字は、日本語（ひらがな・カタカナ・漢字）・英数字・半角の空白・`-`・`_` だけにし、それ以外は取り除く（題名に素材の語が入りうるので、`$`・バッククォート・`%`・`#`・`;` など、シェルや URL で意味を持つ文字を通さない）。
- 案名は、案どうしで重複させない。題名が空になったら `report` にする。
- 保存の前に、カレントフォルダのパスを 1 回だけ確かめる。`"`・`$`・バッククォート・`%`・`!`・`^`・改行・制御文字のどれかを含むときは、拒否する（Git Bash の二重引用符と cmd で意味を持つ文字）。`( ) & ' ~ @ , + [ ]` や全角記号は通す。ファイル名は許可した文字で作るので、再確認はしない。
- 書き込めないとき、またはパスの確認で拒否したときは、そのフォルダには保存せず、保存先を聞く。
- 保存先が許可されたあとは、後続のすべての Bash 呼び出し（手順7・10 の削除、手順8 の `start`、手順9・10 の削除、手順10 の名前変更）で、同じパスを使う。
- 同名のファイルがあるときは、上書きしてよいか聞く。「いいえ」なら、末尾に連番を付けた別名（`-2`, `-3`…）で保存する。連番の名前も既にあるときは、空いている最小の番号まで進める。
- 削除が実行できなかったときは、手順7・11 の報告に「このファイルが残っている。開かないこと」と、残っているパスを明記する。

## HTML の仕様
- 画像（PNG/JPG）は base64 でインライン化する。大きい画像は縮小するか、利用者に確認する。
- グラフはインライン SVG／CSS で描く。`dataviz` スキルが使えるときは、その指針に従う。
- 構成図・フロー図もインライン SVG で描く。矢印に名前を付け、`figure` と `figcaption` で何を示す図かを書く。`artifact-diagramming` スキルが使えるときは、その指針に従う。
- 開いた最初の状態で、読むべき内容がすべて見える。スクロールや操作で現れる仕掛けに頼らない。アニメーションを入れるなら、見える状態から始める。
- 対象は PC の画面（幅 1280px）にする。スマートフォンの表示と印刷には、対応しない。
- 言語は依頼文に合わせる。フォントはシステムフォントを指定する（日本語なら日本語に適したシステムフォントのスタック）。
- ダークモード対応は、依頼文にあるときだけ入れる。入れるときは、色をすべて CSS 変数にする。`:root` に明るい値、`@media (prefers-color-scheme: dark)` に暗い値を定義し、`body` の背景も変数で指定する。
