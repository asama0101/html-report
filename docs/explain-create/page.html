html-report create の動作解説

対象: Claude Code プラグイン html-report v{{version}} の /html-report:create。読み手: このプラグインを初めて見る開発者。

結論: create は、スクリプトを持たない。Claude が、手順書（Markdown {{md_count}} 本）と検査用の関数（dom-check.js）を、必要な手順の直前に読み、ブラウザ操作と Bash で HTML を作って検査する。

この解説は、plugins/html-report/ の実ファイルを読んで作った。標準出力と戻り値は、デモの HTML に対して実行して採取した。

解説読む書く標準出力戻り値解説＝筆者の説明／読む＝実ファイルの文章（そのまま）／書く＝Claude が書く文の例／標準出力＝実行して採取／戻り値＝ブラウザ操作の戻り値

5 スクリプトが機械的に止める条件

解説create の手順書が呼ぶスクリプトはない。機械的に判定するのは、ブラウザ内で動く dom-check.js だけで、止めるかどうかは Claude が戻り値を見て決める。

表 4: 止める（不正とする）条件。判定する側ごと

判定する側止める（不正とする）条件
dom-check.js（ブラウザ内）
  • 使えない要素: template・noscript・iframe・frame・object・embed・base・form
  • 属性名が on で始まるイベント属性
  • srcdoc・action・formaction 属性
  • meta の http-equiv が content-security-policy 以外
  • href・xlink:href・src の値が、# で始まるもの（href のみ）・a の http:/https:/mailto:・img の data:image/ のどれでもない
  • SVG の attributeName が href・src のとき、to・from・values に上と同じ判定
手順書（Claude が判定。戻り値を見る）
  • violations が空でない
  • protocol が file: でない
  • file が手順6 で保存したファイル名と違う（移動したので不正）
  • browser_evaluate がエラーを返した
tests/check_html.py（開発用）
  • 終了コード 1: 外部読み込み・外部への送信・javascript: の URL・イベント属性・骨組み（DOCTYPE・charset・CSP）・必須の語の欠け
  • 終了コード 2: HTML のパスが 1 つ指定されていない
  • 終了コード 0: 問題なし（OK）

6 判断の規則

解説状態・分岐・聞き直しの規則は、手順書の文面で Claude に与えられる。機械は強制しない。

表 5: 判断の規則（SKILL.md と references から）

規則内容

  • 崩れの修正: 1 版につき最大 3 回
  • 安全の検査の修正: 最大 3 回（開く前の確認・DOM 検査・外部リクエスト・protocol・file）
  • 要件との照合の修正: 最大 3 回（上の 2 つとは別に数える）

  • 上書きしてよいかを聞く

  • その項目を外す

  • 手順6 のあと検査の前に止まるとき: 案のファイルを残し、保存先の絶対パスと削除コマンドを伝える。未検査なので開かないよう添える
