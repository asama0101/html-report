## 概要
html-report プラグインの create の SKILL.md と references、および doctor の SKILL.md の環境の判定方法を、人が読んで理解でき、簡素な文面に書き直す。動作は、現在の main（コミット 790cd09）と同じにする。
依頼文の「v0.1.0 と同じ動作」は、依頼者の訂正で、「いまの main と同じ動作」に改めた。#10 の修正と #11 の書き直しは、動作として保つ。直すのは文面だけで、動作の規則は足さず、削らない。
create の references/ の分割は、現在のまま残す。手順の番号・見出し・どのファイルに何を書くかも保つ。同じファイルの中での段落の並べ替えと統合は許す。dom-check.js は、そのままファイルとして残す。

### 入力
依頼文の要約: このリポジトリの SKILL.md を、人間が読んで理解できる形にしつつ、シンプルにする。ただし、動作は変えない（基準は、依頼者の訂正で、現在の main）。
入力ファイルはない。対象は、次のファイル。
- plugins/html-report/skills/create/SKILL.md
- plugins/html-report/skills/create/references/（materials.md・generate.md・verify.md・select.md）
- plugins/html-report/skills/doctor/SKILL.md の環境の判定方法
- 手順の見え方が変わって食い違うときの、README.md と docs/images/ の図
- tests/test_plugin.py（落ちる検査があるときだけ）
- 版の 3 か所（plugin.json・pyproject.toml・doctor の表示例）

## 流れ
1. 現在の main の create の規則を 1 つずつ挙げ、規則・現在の所在・新しい文面での所在を持つ対応表を作る。規則 1 つは、守る・止まる・禁止のいずれかの文 1 つとする。対応表は、.gitignore の対象の docs/superpowers/ に置く。
2. create の SKILL.md と references を、手順の番号・見出し・ファイルの分け方を保ったまま、文面だけ簡素にして書き直す。
3. doctor の SKILL.md の環境の判定方法を、create と同じ文面に直す。doctor のそれ以外の部分は変えない。
4. 対応表で、すべての規則が新しい文面のどこにあるかを確かめる。
5. 別のエージェントに、main の文面と新しい文面を読ませ、動作が変わる箇所を挙げさせる。指摘を直したあと、同じ観点で再確認し、指摘が 0 件になるまで繰り返す。
6. README.md と docs/images/ の図が、新しい文面と食い違うときだけ直す。
7. 版を v0.1.2 に上げる（plugin.json と pyproject.toml は 0.1.2、doctor の表示例は v0.1.2）。
8. pytest と ruff を通す。落ちる検査があるときは、その検査が守っているものを 1 件ずつ見る。動作を守る検査は、文面を戻して通す。書き方だけを見ている検査は、tests/test_plugin.py を直してよい。
9. tests/SCENARIOS.md の手動シナリオを、全件流す。
10. 利用者が、commit する前に、新しい SKILL.md を通読する。

## 受入条件
- 対応表で、現在の main の全規則が、新しい文面のどこかに対応している（抜けが 0 件）。
- 別のエージェントのレビューで、動作が変わると指摘された箇所が 0 件になっている。
- create の SKILL.md と references 4 ファイルの合計の文字数が、wc -m で数えて、現在の main より減っている。
- 利用者が、commit する前に新しい SKILL.md を通読して、人間が読んで理解できる内容になっていると答えている。
- pytest と ruff が通っている。動作を守る検査は、緩めていない。
- tests/SCENARIOS.md の手動シナリオが、期待どおりの結果になっている。流せなかったときは、その旨を完了の報告に明記し、対応表と差分レビューの結果で受入とする。
- 版が、plugin.json・pyproject.toml・doctor の表示例の 3 か所で v0.1.2 にそろっている。
- create と doctor の環境の判定方法が、同じ文面になっている。
- dom-check.js が、変更されずに残っている。

## 非目標
- doctor の、環境の判定方法以外の部分を直すこと。
- v0.1.0 と現在の main との差を整理すること。

## リスク
- 簡素にする書き直しで、止まる条件や禁止事項などの規則が落ちるおそれがある。対応表と別のエージェントのレビューで確かめるが、見落としは残りうる。
- 「人間が読んで理解できる」の判定は、利用者の通読に頼るため、主観になる。
- tests/SCENARIOS.md の手動シナリオは、Playwright と時間が要る。流せないときは、動作が同じことの証拠が弱くなる。
